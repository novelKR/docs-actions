# 유지보수와 소비자 갱신

[English](maintenance.md) | [한국어](maintenance.ko.md)

## 중앙 변경

공개 workflow 인터페이스는 v1을 유지한다. [JSON 계약](../contracts/pages-deploy-v1.json)은
입력 타입·기본값·필수 여부, 출력, 권한, 이벤트, 범위, 금지 기능, 실행 환경과 동시
실행 설정을 모두 담는다. 검사기는 전체 문서를 지원 인터페이스 및 실행 YAML과
대조한다. 알 수 없는 키와 중복 YAML·JSON 키는 실패하며 CI의 검사 생략이나 오류
무시도 허용하지 않는다.

정상적인 `actions/deploy-pages` 보안 갱신은 workflow와 JSON의 `runtime.action`
**양쪽**에서 전체 SHA를 바꾼다. 병합 전 실제 원격 commit과 라이선스를 검토한다.
SHA 형식이 맞다는 것은 신뢰나 실존의 증명이 아니다. 허용 목록은 여전히 공식
배포 저장소의 단일 단계만 허용하며 새 권한·명령·입력을 추가하지 않는다.

갱신을 통과시키려고 과거 workflow fixture를 바꾸지 않는다. 과거 blob 무결성
검사와 현재 정책 검사는 별개이므로 실행 코드 갱신이 과거 YAML과의 완전 일치를
요구하지 않는다. 인터페이스·기능 변경은 의존성 갱신에 섞지 말고 계약 변경으로
별도 검토한다. Dependabot PR은 제안일 뿐이다. 필요할 때 정책을 함께 갱신하고
봇의 동작을 사용자 승인으로 표시하지 않는다. 기존 의존성 PR은 별도로 유지할 수 있다.

중앙 main에 `contracts` 검사와 code-owner 검토를 요구한다. 소비자 브랜치와 환경은
별도로 보호한다. 일반 유지보수에서 어떤 스크립트도 보호 규칙, 권한, Pages 설정이나
저장소 공개 범위를 변경하지 않는다.

## 소비자 SHA 갱신

중앙의 diff, 라이선스 범위와 해당 main-push CI 성공을 검토한 뒤 실제 전체 commit
SHA만 채택한다. 소비자 PR에서 workflow 참조와 lock 또는 현재 검증용 snapshot을
함께 갱신한다. 정확한 원격 workflow 바이트와 snapshot을 대조하며 검사 실패를
없애려고 해시만 고치지 않는다. 과거 AGPL fixture를 실행용 대체본으로 사용하지 않는다.

소스·산출물 무결성과 공개 경계를 포함한 소비자 필수 검사를 실행한다. 소비자 PR은
배포하지 않아야 한다. 환경 정책에 따라 병합·공개 승인 후 배포 결과와 실제 제공되는
빌드 명세를 확인한다. 중앙 CI만으로 소비자 사이트나 OIDC 실행을 검증할 수 없다.
중앙 main 변경은 SHA로 고정된 소비자를 자동 갱신하지 않는다.

기존 gateway 이관 스크립트는 병합 전 PR #52의 특정 기준만 이해한다. pin 갱신
도구가 아니며 현재 main에서 실행해서는 안 된다. 신규 소비자는 호출 예제를 사용하고
이미 연결한 소비자는 검토한 pin 갱신 PR을 사용한다.

## 게시 순서와 복구

전체 main workflow와 배포 작업에 서로 다른 동시 실행 그룹을 사용한다. 진행 중인
main·배포 실행은 취소하지 않으며 오래된 PR 검사는 취소할 수 있다. 동시 실행 제어는
최신 commit 우선 게시를 보장하지 않으며 영속적인 FIFO 큐도 아니다. 게시 전 과거
재실행과 대기 중인 승인을 확인한다.

중앙 SHA를 되돌리면 배포 코드가 바뀌지만 이미 게시된 내용은 바뀌지 않는다. 사이트
내용은 소비자의 검토된 소스·산출물 절차로 복구한다. 이 workflow는 현재 실행의
산출물만 소비하며 만료된 산출물이나 다른 실행의 산출물을 조회하지 않는다. 과거
main 실행의 재실행은 산출물 보존 여부와 현재 환경 규칙에 따라 해당 실행의 결과를
의도적으로 다시 게시하는 작업이다.

## 검증 한계

PR 전에 [README](../README.ko.md)의 명령을 실행한다. 검사는 금지 기능, 전체 계약
일치, 과거 바이트 보존, MIT 표지, 로컬 문서 링크와 두 언어 코드 예제 일치를 다룬다.
번역 의미, 원격 링크, 권리 보유와 법적 허가는 여전히 검토가 필요하다. PyYAML은
버전 고정이며 해시 잠금은 아니다. 지원 플랫폼의 배포물을 해시 고정하는 작업은
별도 의존성 변경으로 다룰 수 있다. 기본 테스트는 실제 API를 호출하지 않는다.
